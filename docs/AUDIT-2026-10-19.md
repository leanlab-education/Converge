# Latent-Bug Audit — 2026-10-19

**Trigger.** On 2026-10-19 Amber reported Batch 65 as "still being scored" on the admin
side while both annotators saw "Complete, 55 of 55 items scored." Root cause: one
criterion score had been lost by the scoring screen's auto-save in August, and the
annotator project page counted an item as scored when it had *any* score. PRs #11
and #12 fixed those two things the same afternoon. This audit asks the obvious next
question: where else does the codebase have that shape — a client-derived state that
disagrees with the server, an async write that can drop work, or a label that
conflates "I am done" with "the unit of work is done" — and what else is latent.

**Method.** Seven read-only reviews, one per subsystem (release lifecycle, scoring
reads/writes, reconcile/adjudicate UIs, admin batch/team management, export/IRR,
auth/authorization, activity/schema/infra), each briefed on the Batch 65 shape and on
the 2026-06-18 production-readiness audit so already-fixed items were not re-reported.
Every finding that became a fix was re-verified by hand against the code, and the
live database was scanned for evidence of each data-integrity finding before it was
prioritized (Section 4). Reviewer findings that could not be traced to a code pointer
were dropped.

**Headline.** The lifecycle invariants hold on today's production data: no release is
stuck or wrongly complete, every reconciled final is stored under the correct owner,
no score exists outside its scorer's assignment or criteria. The serious findings are
*latent*: paths that destroy or mislabel paid annotation data if an admin takes an
ordinary action (delete a user, add a fifth team, re-open an adjudicated criterion,
import a CSV with a misspelled column). Two items need a human decision today
(Section 1). Everything else fixable in a reasonable PR has a PR (Section 2); the
rest are recommendations (Section 3).

### PR-A (#14) — Guard destructive deletes and team edits

| ID | Sev | Finding |
|----|-----|---------|
| U1 / E3 / A6 / I3 | **P0** | `DELETE /api/users/[userId]` deleted the user with no guard, and `Score.user` cascades. Reconciled finals are stored under the release owner's `userId` (first member by email), so deleting one annotator deleted the whole pair's finals in every batch, plus their escalations and admin re-opens. Now refused (409) when the user has scores, escalations or unlocks; schema moves to `Restrict`. |
| A3 / I5 | P1 | Deleting a team cascaded its releases but left the members' `BatchAssignment` rows with `teamReleaseId = null`, which every reader treats as legacy "whole batch, every criterion" access. Assignments are now deleted with the team. |

| L7 | P2 | An adjudicator could not be assigned on a COMPLETE release, but the edit-after-COMPLETE flow needs one to escalate. Allowed for `adjudicatorId` only. |

### PR-B (#15) — Release lifecycle: never strand, demote, or prematurely complete

| ID | Sev | Finding |
|----|-----|---------|
| L1 / A2 | P1 | `syncBatchStatus` mapped `[COMPLETE, COMPLETE, DRAFT]` to DRAFT. Creating a team (or using the team picker) creates a hidden DRAFT release on every batch, so adding a fifth team would have demoted every finished batch to DRAFT: hidden from the final exports, shown inactive, deletable. Rollup now ignores never-started releases when any release has progressed; stub releases are not created on COMPLETE or locked batches. |
| L2 / R3 | P1 | Re-opening a criterion with an adjudicated cell: a revision that now disagrees deleted the final but left the resolved `Escalation`, so the hub showed a locked "set by the adjudicator" panel with no value, the pair could neither record nor re-escalate, and the release could never complete. The escalation is now cleared with the final. |
| L3 | P1 | A criterion could be re-opened on a release still SCORING; one revision flipped it to RECONCILING, 403-ing the partner's remaining scoring, and completion never checked that every item was scored. Re-open now requires RECONCILING/COMPLETE; revision never leaves SCORING; completion asserts fully scored. |
| L4 | P1 | A failed `maybeAdvanceReleaseAfterScore` (swallowed by the scores route) left a 100%-scored release in SCORING with both partners shown "Waiting on partner." The annotator project page now self-heals such releases. |
| L5 / L14 | P1 | Withdrawing an escalation never re-evaluated completion (RECONCILING with nothing left) and ignored the batch lock. Fixed. |
| L9 / R5 / L13 | P2 | Escalating on a COMPLETE release left it COMPLETE with an open escalation (and `finalizedBatchesOnly` exported the old final); the escalate route validated the criterion against the project, not the team. Fixed. |
| L8 | P2 | Re-open moved the release to RECONCILING without syncing the batch, so the batch read COMPLETE for the whole revision window. Fixed. |
| L12 | P2 | The revise route's upsert + re-derivation ran outside a transaction. Now serializable, P2034 → 409. |
| R6 | P2 | After a re-open, the annotator saw a phantom "1 to reconcile" task leading to an empty hub. Suppressed while nothing is unresolved and an unlock is open. |

## 3. Open — recommended follow-ups (not fixed here)

Ordered by what I would do first.

1. **Persist the release owner and the slot.** The owner slot (`team.members[0]` by
   email) and each annotator's slot are recomputed from live email order on every
   read. No API changes emails, but a manual rename (done once, 2026-09-09) that
   crosses the partner's email would make every existing final invisible and swap
   the pair's halves (L10 / S3). Add `ownerUserId` to `TeamBatchRelease` and
   `slotIndex` to `BatchAssignment`, written once at creation. *P1 if emails are
   ever edited; otherwise dormant.*
2. **Token revocation** (audit P6): no `tokenVersion`; a password reset does not
   invalidate a compromised session for up to 8h; a demoted or deleted admin keeps
   their JWT role claim. Medium effort; touches the auth callbacks.
3. **Rate limiting** (audit P4): login, reset-password, invite-accept are unthrottled.
   Needs an Upstash (or similar) decision; fail open when unset.
4. **Audit log for the unblinding export** (audit P5) and for role changes, invites,
   account deletion.
5. **Pseudonyms do not blind annotators** (E4 / I11): `displayAnnotatorName` returns
   "Pseudonym (Real Name)" and several annotator surfaces ignore the setting. The
   flag is off on every project today. Needs an annotator-facing variant on the
   project page, reconcile hub, `my-team` and the batches response.
6. **Per-project time** (I8): the Annotators tab "Time" column is platform-wide;
   multi-project annotators are counted in every project. Capture `projectId` on
   heartbeat or relabel the column.
7. **IRR headline** (E8 / audit N-1): macro-average of rounded per-team
   percentages with no minimum sample; `isReady` is shipped but never rendered.
8. **Visibility flags** (A13): per-release "hide" leaves status SCORING while batch
   unpublish sets DRAFT; `isHidden` has no setter; `isAssigned` has no reader.
9. **Legacy single-scorer path** (A15 / audit P7, M-L1, M-L2): still live in the UI
   and two routes though CLAUDE.md calls it retired; decide one model.
10. **Surfaced while building the fixes:** replacing an annotator who leaves
    mid-study has no supported flow (teams freeze once scoring starts, and PR-A
    (#14) now enforces that on the team picker too); the Export tab does not yet
    display the new conflict count PR-D (#16) returns; the reconcile screens use
    `text-warning` / `bg-warning` classes that have no token in `globals.css`;
    `AUTO_RECONCILED_NOTE` is duplicated between `export.ts` and
    `reconciliation.ts`; `POST /api/users` does not enforce the 8-character
    password minimum the invite and reset routes enforce.
11. Smaller: unguarded `request.json()` in most mutating routes (audit M-API1);
    `durationSeconds` never written and timing docs inaccurate (S9); TRAINING
    batches cannot re-open a criterion (L15); dead discrepancy computation on the
    root dashboard (R14); `computeDailyActivity` read-then-upsert race (I12);
    discrepancy report silently drops cells without exactly two scorers (E5);
    `batches` GET N+1 (audit M-API4).
